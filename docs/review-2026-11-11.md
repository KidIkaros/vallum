## Fixed in `4658c0a`

| # | finding | why it mattered |
|---|---|---|
| 1 | The reader's peer-exemption set refreshed only on the `recv_timeout` **timeout** arm | Under load the queue is never empty, so the arm never fires: the set stays empty, every configured peer is bucketed, and the throttle removes the idleness that would lift it. A tunnel with three active peers loses ~95% of packets. Now refreshes on a 100 ms deadline, checked per iteration. |
| 2 | `unwrap_or(true)` on a poisoned mutex | Admission off for the life of the process. Fails closed now. |
| 3 | Bundle hook count omitted `pre_down` | `pre_down` runs `sh -c` as root on detach, so a stranger's bundle carried a root command that imported with no finding — not even under `--strict`. |
| 4 | `path_stalled` required `sent_age < 120 s` beside a keepalive-derived limit | A legal 300 s keepalive made a stall undetectable; 60–120 s made the gauge flap. Both ages now share the limit. |
| 5 | `doctor` derived the enrol port as `listen + 1` | Ignored `[enroll] port`, so it inspected a port nothing listens on and passed. Also reported PASS when `[enroll] enabled` had no unit running. |
| 6 | `build.rs` watched the worktree-private git dir for the ref and `packed-refs` | Both live in the **common** dir, so in a linked worktree the stamp froze again — the exact failure that file exists to prevent. |

## Fixed in `2e73320`

1. **`packaging/vallum-ops` baked machine-specific values into a root-installed
   dispatcher.** `REPO=${VALLUM_REPO:-/home/ikaaros/Coding/Gold/vallum}` and
   `ssh -p 2222 -i /home/ikaaros/.ssh/id_ed25519_basanite_vps buffy@10.7.0.1`
   inside `trace`. Combined with `sync`/`self-update` exec'ing `$REPO/scripts/*`
   as root under a NOPASSWD sudoers rule, that is root for anyone who can write
   the checkout — the escalation ADR-0029 already names, now with a hardcoded
   path that also makes the dispatcher wrong on any other host.
**Fixed**: no baked-in `REPO`; the path comes from a root-owned
`/etc/vallum/repo` or `VALLUM_REPO`; `require_trusted_source` refuses a tree that
is not root-owned unless a root-only marker opts in, loudly; and `trace`'s load
generator is `/etc/vallum/trace-load`, run as an argv, with no host, key or port
in the file.

2. **`write_private` sets `0600` only when it creates the file**, and follows
   symlinks. With `--force`, or a pre-existing `client.key` at 0644, the bundle's
   private key lands world-readable; a pre-planted link redirects the write.
3. **`check_config_ownership` inspects the config file but not its parent
   directory.** A root-owned 0600 config in a world-writable directory passes,
   and anyone who can write that directory replaces the file — whose `pre_up`
   then runs as root.
4. **The admission exemption was keyed on the peer's `SocketAddr`**, which on a
   client is the server's public `host:port`. **Fixed**: a configured peer gets a
   large finite allowance (burst 4096, 20,000/s ≈ 280 Mbit/s) instead of a free
   pass, so a spoofer is bounded rather than unlimited. It is a bound, not a
   solution — admission after the first authenticated packet needs its own ADR.

## Open — correctness and process

5. **Enrolment still warns and sends when `applied` is false.** Refusing looked
   right until the suite showed `applied: false` also means "there was no daemon
   to ask" (standalone responder, `--no-apply`). The fix is for the report to
   carry `apply_attempted`, so a real failure can be refused and a deliberate
   skip cannot.
6. **`widen_to_tunnel` picks the first same-family network without a containment
   test**, so a server with two subnets of one family hands peers a prefix from
   the wrong one — the off-link failure the widening exists to fix.
7. **SPDX headers are missing** on `crates/vallum/build.rs`, `scripts/trial.sh`,
   `scripts/vallum-sync.sh`, `packaging/vallum-ops` and the `gui-*` scripts,
   against CONTRIBUTING's rule.

## Standards axis

- **`#![forbid(unsafe_code)]` was downgraded to `deny`** to admit
  `libc::mlockall` in `privileges.rs:148-152`. CONTRIBUTING says no `unsafe` in
  Vallum-owned crates, and that a change to the security posture wants an ADR.
  None covers it. *(Verified: the attribute at `lib.rs:43` is `deny`, and the
  unsafe block is real.)*
- **`sh -c` in admin tools**, against CONTRIBUTING's "argument arrays, never
  `sh -c`": `install.sh:403,416` (the second interpolates `$SUDO_USER` into a
  `sed` that writes sudoers) and `trial.sh:81`.
- **Doc comments attached to the wrong item**, six times, from the same insertion
  mistake: `run.rs:295` (`run`'s doc heads `path_stalled`), `net.rs:1015`,
  `privileges.rs:139`, `device/mod.rs:327`, `doctor.rs:496/763/1006`.
- Judgement-call smells worth doing eventually: egress is a `String` compared to
  `"full"` at six sites while `uapi` claims to be "the one place this decision is
  made"; the five `handshake_dropped_*` counters mirror `HandshakeDrops` by hand;
  the stall threshold is written twice; `owns_endpoint` is a middle man.

## Spec axis

Load-bearing claims hold: the `/20` default, the client-prefix widening, the
hook refusal, the 16 MiB control cap, the daemon-side build stamp, and ADR-0031's
scoped timestamp guard (its test passes, and teardown at 180 s makes the bound
real).

Two claims did **not** hold, and one is fixed above: ADR-0032's "up to one tick"
bound was false under load (fixed), and ADR-0033's report omits the
privilege-drop line while justifying the omission with "the systemd unit already
drops privileges" — the unit has no `User=`, and the daemon drops only when the
config sets `user`. So R2-2's "no `user` runs as root" is still unreported.

Scope creep, by the roadmap's own rule that unmapped work is not
production-readiness: a UTCP tool surface with a 776-line manual, a Tauri/React
console rewrite (~11.9k lines), exit-notice/deadman packaging, and GUI smoke
scripts.
