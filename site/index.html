◆ Vallum
Documentation Source

A tunnel whose handshake is built for the day the quantum computer arrives.

Vallum is a layer-3 VPN for Linux: a server and a client you deploy, not a reference crate. Every handshake combines X25519, sntrup761 and ML-KEM-768, and every identity is signed with Ed25519 and Falcon-1024 under a CA-issued validity window.

Install

sudo ./scripts/install.sh --from-release

# server: key, config, IP forwarding, firewall, NAT, systemd units
sudo vallum setup --server

# client with SSH access: it generates its own key, only the public line crosses
sudo vallum setup --remote you@vpn.example.com

A client without SSH takes one invite ticket instead (sudo vallum peer invite laptop, then sudo vallum join vallum1-join:…) — the private key never leaves the machine. See the client guide.

What the handshake does

Suite 0x0003
X25519 + sntrup761 + ML-KEM-768, combined with HKDF-SHA3-256. Three messages, three hybrid KEM operations, one round trip.
Signed identities
Ed25519 + Falcon-1024 over the transcript, with a signed validity window so a key can expire without being revoked by hand.
Epoch discipline
Rekey is a fresh hybrid handshake, not a re-use of the old one; the superseded epoch is erased after REJECT_AFTER_TIME.
Rotation without an outage
vallum peer rotate accepts the old and the new key at once, and peer finalize retires the old identity when the client has switched.

What it is not

  • Not cross-platform. Linux is the supported target (ADR-0005), and macOS is out of scope (ADR-0011).
  • Not a hosted service. You run the server, and you hold the keys; there is no account to create.
  • Not a relay. NAT traversal and relaying are bounded by a written list of what we will and will not do (ADR-0016).
