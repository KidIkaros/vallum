A tunnel built for the day the quantum computer arrives

Vallum is a layer-3 VPN for Linux with a tri-hybrid post-quantum handshake. Open an account at a desk, enrol devices on demand, and keep every private key on your own machine — or run the desk yourself and offer the same tunnel to your own users, human or agent.

◆Two ways in

For humans

  1. Open an account

    Sign up at a desk with an invite code, or anonymously where the operator allows it. You get an account number — the account is created on its own; devices come next.

  2. Keep the account number

    32 hex characters, the only credential. No email, no password reset — the desk holds no personal data and no private keys (ADR-0045).

  3. Enrol a device

    From your account page, add a device: the desk mints a single-use join ticket bound to your plan. The client generates its own key; only the public line crosses to the server.

  4. Join, then add more

    vallum join 'vallum1-join:…' brings the tunnel up. The account page mints fresh tickets for further devices under the same plan.

A ticket lives 15 minutes; the account outlives it. An expired ticket is not a lost account — add a device again, no new invite code.

For agents

POST /api/signup
  {"code": "…"}
  → account number (no device yet)
POST /api/devices
  {"token": "…", "name": "agent-01"}
  → a single-use join ticket, bound to the plan
POST /api/account
  {"token": "…"}
  → plan, byte pool, devices

The desk is a JSON API first: credentials ride in the body, never the URL. A UTCP manual ships in the repo, so an agent can discover the flow and enrol headlessly — no browser, no TTY. On the tunnel itself, every read verb answers --json and vallum tui --snapshot renders a TTY-free view (ADR-0039).

◆Run your own desk

The desk is the account layer, not the tunnel. It is stdlib Python and one systemd unit, and it never edits the daemon's config — it only calls vallum peer invite/remove/show and reads the daemon's own counters. A desk bug cannot weaken the tunnel; worst case it mints or removes a peer.

  • One server per desk. A desk enrols against a single Vallum server; capacity is that machine's hardware, not a fleet. There are no regions, and multi-server is future work (ADR-0047).
  • Plans are rows. A paid tier is data on the account row — plan, expiry, byte cap — so a billing webhook only ever updates a row.
  • Your brand. --operator-name sets the desk's page header; invite codes, trial limits and device caps are operator flags.
  • Backups ship enabled. A timer copies the account database through SQLite's online-backup API and verifies the copy before keeping it.

◆What the handshake does

Suite 0x0003
X25519 + sntrup761 + ML-KEM-768, combined with HKDF-SHA3-256. Three messages, three hybrid KEM operations, one round trip.
Signed identities
Ed25519 + Falcon-1024 over the transcript, with a signed validity window so a key can expire without being revoked by hand.
Epoch discipline
Rekey is a fresh hybrid handshake, not a re-use of the old one; the superseded epoch is erased after REJECT_AFTER_TIME.
Rotation without an outage
vallum peer rotate accepts the old and the new key at once, and peer finalize retires the old identity when the client has switched.

◆The cockpit

Humans get vallum tui — a real operations console over SSH. The alpha ships the CLI, the TUI and the UTCP manual; the desktop console stays a development surface (ADR-0039).

◆Install

For your own server. Joining the hosted alpha needs only the client.

sudo ./scripts/install.sh --from-release

# server: key, config, IP forwarding, firewall, NAT, systemd units
sudo vallum setup --server

# client with SSH access: it generates its own key, only the public line crosses
sudo vallum setup --remote you@vpn.example.com

A client without SSH takes one join ticket instead (sudo vallum peer invite laptop, then sudo vallum join vallum1-join:…) — the private key never leaves the machine. See the client guide.

◆What it is not

  • Not cross-platform. Linux is the supported target (ADR-0005), and macOS is out of scope (ADR-0011).
  • Not a fleet. One self-hosted server per deployment, sized by its hardware. No regions, no anycast, no autoscaling claims (ADR-0047).
  • Not a relay. NAT traversal and relaying are bounded by a written list of what we will and will not do (ADR-0016).
  • Not audited. The post-quantum legs ride an experimental SDK and no external audit has been performed. Read the security model before you deploy.
